# Manual synthetic journey editor — batch 16

The optional **Add manual test case** action lives inside Conversation map → Journey testing. Normal automatic checks stay unchanged. Opening the composer exposes bounded synthetic number and short-answer controls alongside supported finite choices. Display steps receive no invented values; unsupported required inputs block review and optional unsupported inputs are identified as untested.

Inputs are volatile until explicit save. Number lexemes remain strings, including distinctions such as `1`, `1.0` and `01`. The shared helper validates representation and uses existing routing/scoring; the UI does not copy those rules. A clear synthetic-only acknowledgement is required before reviewing/saving. The input fields explain the number/text limits and the fact that number step increments are not tested.

## Deliberate review

Review shows the exact case name, observed status, result/tier ID, numeric or absent score, visible question IDs and answers in order, category scores/null/coverage, ordered result sections, omitted inputs and unsupported inputs. It explicitly says that accepting this behavior as a baseline does not prove the answer or recommendation correct. Saving appends one new case; it never replaces a previous expectation.

Cancel review and Escape preserve typed controls without writing storage. Escape closes a review first, then the manual composer, then the existing conversation dialog. The composer can be reopened with its volatile inputs while Journey testing remains mounted. Leaving that view, closing the dialog or switching quiz discards volatile inputs. Review heading focus is measured against the existing sticky dialog header, and focus restoration defers to any newer focused control.

Changing any input, raw case name, draft fingerprint or loaded library invalidates the review. Confirmation rereads exact current storage bytes and delegates revalidation/recomputation to `applyManualJourneyCase`. A quota or read error keeps the prior library and current inputs/review. Same-tab changed bytes are caught even without a storage event; another-tab events visibly request an explicit reload. Reload preserves manual inputs and makes pending reviews stale.

## Storage, migration and portability

The existing per-quiz key and combined 25-case limit remain. Choice-only libraries keep version 1; mixed typed libraries use the new strict version 2 codec. Existing readable legacy case objects are not automatically repaired, upgraded or rebaselined. Strict validation gates new appends, promotion, import and expectation upgrades. Unknown/newer formats remain untouched after errors. Explicit removal is the sole legacy exception: after an unchanged-raw check, it removes one uniquely identified case while preserving unrelated version-1 envelope properties and all remaining case objects. This lets a creator remove a readable historical case without silently normalizing its neighbours; mixed/version-2 removal still uses the strict codec.

All touched parent writes compare current raw bytes to the reviewed/loaded baseline immediately before saving. A single `localStorage.setItem` succeeds as a whole, but the preceding read/check/write is **not** cross-tab compare-and-swap. Two writes can still interleave. An already-open older application tab can overwrite the shared key using old code. Visible copy asks creators to refresh or close older tabs first; no transactional or mixed-version recovery claim is made.

Typed JSON exports include the exact synthetic numbers/text, without redaction. The export acknowledgement is pinned to the displayed raw library and import-file baseline; storage/reload/write changes invalidate it. Export refuses a raw-library mismatch before download. Imported typed cases require acknowledgement and expose inert exact values/types/question IDs for review before saving. Stored manual cases have the same disclosure. No typed text is rendered as HTML or converted into a link.

## Findings repaired and evidence retained

- Initial Chrome exposed a real cancellation focus bug: a combined open/review effect focused the composer heading when review closed. Separate opening effects now leave closing focus to its explicit handler.
- Initial WebKit exposed a real post-save focus bug: a genuine pointer save left `document.activeElement` on the dialog. The handler now recognizes the trusted native save interaction while retaining the deferred newer-control guard. An untrusted scripted click with another input focused still preserves that input. The pre-fix focus metadata is retained in `webkit-focus-evidence/failure-focus.json`.
- The existing expanded-case regression caught a changed quota-error message. Storage read/write failures now retain the established friendly preservation message; explicit stale-library and validation errors remain specific.
- Diagnostic copies temporarily bypassed only the identified focus assertion to inspect later handlers. They are **not acceptance passes**. One WebKit diagnostic reached the final error assertion with a local homepage RSC access-control message. The auxiliary tab used only for same-origin storage writes was isolated to the existing static `robots.txt` resource. Final tests kept the strict empty page-error assertion without filtering. Chromium and WebKit still recorded cancelled/aborted local background RSC prefetch requests during navigation, with no final page errors. That observation is preserved, not claimed as proof that all navigation/network behavior is flawless.

Initial failures, diagnostics and intermediate accepted runs remain beside final evidence. No runtime, test or documentation edits remain pending in this lane.
