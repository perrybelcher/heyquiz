# Pippi observed beta kit

Run with 3–5 people who have not used the editor. Include a marketer, an ecommerce seller, and a nontechnical business owner. Aim for one real iPhone/Safari and one real Android/Chrome session. Use fictional products and test-only contacts; CRM and payments are out of scope.

## Moderator opening

“We’re testing the product, not you. Please say what you expect and what you’re thinking. If something is confusing, that’s useful feedback. I’ll mostly stay quiet.”

Ask permission before recording. Do not record password entry, confirmation links, or personal customer data.

## Participant task — send this, without a walkthrough

Open https://www.pippiapp.com/signup and create a free account. Confirm the email, then build a three-question quiz for a fictional desk-accessory shop. Recommend a small desk kit to people short on space and a larger kit to people with more room. Make at least one answer affect the recommendation. Give the quiz your own colors. Preview both recommendations, publish it, and send yourself the public link.

Open that link on your phone. Complete it, then return to the builder and find the response and completion analytics. Finally, change one question and make sure the public quiz shows your update.

When finished, explain what you found easy, what was confusing, and whether you trust the scoring and analytics.

## Moderator checkpoints — do not coach first

| Task | Evidence to record | Pass condition |
|---|---|---|
| Register and confirm | Delivery time, Inbox/Spam, callback result | Opens authenticated workspace |
| Build | First hesitation, wrong clicks, help requests | Three questions saved without assistance |
| Scoring | Answers tried and resulting recommendation | Participant can explain why each outcome appeared |
| Theme | Time to find control, preview appearance | Can change colors without guidance |
| Publish | Confusion about draft vs live | Public link works signed out |
| Mobile completion | Device/OS/browser, keyboard and scroll issues | Every question and result usable |
| Results | Ability to find recorded response | Correct result and one completion visible |
| Republish | Whether user realizes a new publish is needed | Anonymous public link shows new question |

After two minutes stuck, ask “What would you try next?” Before offering help, record the task as assisted. Never mark a coached completion as independent success.

## Real-device checklist

- Portrait and landscape: no clipped controls; readable text at enlarged system font size.
- Keyboard: email entry and validation visible; Continue/Submit reachable with keyboard open.
- Touch: answer selection and navigation work without accidental taps.
- Safari and Chrome: confirmation link opens in requesting browser; helpful recovery if opened elsewhere.
- Upload a harmless test image where enabled; camera/file picker returns to the same quiz.
- Briefly lose connection while editing; return online and retry; edits preserved.
- Submit, switch apps, return: no repeated completion or duplicate contact.
- Embedded quiz: test on the actual host site, including scrolling and completion.

## Decision rule

Pause broader invitations for any data exposure, lost work, broken registration/public links, or incorrect scoring. Fix and rerun the failed path first. For usability, target all participants completing registration, publication and a response; record independent versus assisted completion separately. Three to five users reveal friction, not a statistically reliable conversion lift.

## Issue template

Tester ID / device / OS / browser / task / expected / actual / reproducible steps / support reference / screenshot with personal data removed / severity / owner / fix / retest result.

P0: exposed data or lost work. P1: cannot finish core journey. P2: confusing or slow but recoverable. P3: cosmetic.
