Recipient and artifact immutability, canonical links, revocation checks and safe diagnostics remain intact. Existing jobs and absent configuration retain the exact legacy message. This adds no real sender or scheduler. [Copy contract](overnight-result-email-copy.md).

Publication revalidates expanded copy against the current quiz title and brand: an invalid expansion returns a helpful 422, preserves the editable draft and leaves the prior published version untouched. The saved-report allowlist does not include email configuration. The synthetic recovery rehearsal now also proves that an encrypted pending copy survives restoration with its original key and purpose.

The native PDF renderer now measures the next block's actual entry reservation, including paragraph-to-label carry, before drawing a heading. The reproduced rental-report heading, advice and coverage now stay together on page 3. Long text continues to flow, and existing score groups, labels, links, continuation headers, page budgets and glyph fallback retain their behavior. Review also added public projection omission and publication-time expansion validation. These were corrected before compiled acceptance.

The first successful editor run produced poorly positioned screenshots inside the existing scroll container. The PDF browser's first sandboxed Chrome launch failed before fixtures; that log was retained and the authorized local launch passed. No application test failure was relabelled as a production pass.

Pending-copy recovery is browser-tab storage, not cross-device account history. Text exceeding the recovery bound or unavailable storage remains visibly unsaved. A future real mail client may auto-link plain text; HTML generated here contains only the canonical result link. Copy version 1 needs an explicit future version contract to change queued rendering semantics.

Production signup/confirmation/recovery inbox delivery, cloud storage/permissions/load, hosting PDF execution, deployment rollback, historical backup privacy and unaided human usability still require separate verification.
