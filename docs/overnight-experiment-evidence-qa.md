## What the independent checks establish

- Source/campaign filters distinguish absent attribution, literal `unknown` values and referrer hosts. UTC date cutoffs include the exact boundary, all-time adds only its expected historical row, and preview/future/foreign-owner/foreign-quiz records do not inflate counts.
- Counts use the exact canonical published snapshot: an older publication, unknown publication, renamed answer or changed question with the same publication timestamp cannot enter the evidence. Reordered object keys preserve identity. The separate 64-character wording key stays stable when another wording enters analytics, while existing row-ID behavior remains unchanged.
- No quiet sessions or no instrumented sessions produce an actionable-evidence rejection rather than invented results. Unsupported selected publication/wording/type is rejected; unpublished draft edits do not change the published observation.
- Real signed proofs reject wrong owner, source, snapshot, purpose, tampering, trailing token material and the exact 15-minute expiry boundary. New traffic does not replace a previously reviewed observation. Missing signing configuration disables the optional evidence path while ordinary manual experiment creation still works.
- Any valid retirement receipt blocks the quiz ID, including same-ID recreation with copied snapshot bytes/timestamps. Malformed or wrong-owner receipts fail closed. A publication or retirement change during aggregation prevents issuance of a stale signed observation.
- Owner/origin checks occur before expensive reads. Private/no-store evidence responses carry aggregate JSON only; the short-lived proof travels in its dedicated header. Handoff URLs reject counts/proofs/unknown or duplicate selector parameters. Respondent answer/contact sentinels never enter the evidence DTO.
- Declared, chunked and multibyte request bodies respect the byte cap; the reader cancels excess input. Invalid UTF-8/JSON/content types, forged body counts, malformed selectors and cross-scheme origin attempts are rejected without writes.
- Successful launch freezes the reviewed aggregate and plan, not a live recomputation. Legacy/manual creation remains evidence-free. Status-only PATCH cannot replace evidence or plan. A proof cannot be moved to arm B or used without the reviewed plan.
- Publication/retirement changes injected during the experiment write trigger compensation that removes only the new experiment; an existing experiment remains. Injected cleanup failure returns an explicit private 503 and no bearer/private payload. The unconfirmed record can remain when cleanup fails: compensation is best-effort, not a transaction or proof that no record exists after every failure.

## Independent UI review finding

Read-only inspection found an obsolete-loading-state race in `Experiments.tsx`: hold Refresh results, start Refresh evidence, let the listing return a changed source snapshot, then resolve the old evidence response. Its context check correctly prevents stale data, but its `finally` originally cleared the loading boolean only for the old matching key. The obsolete request could therefore leave “Verifying…” indefinitely. The UI owner confirmed it, changed loading to a source-keyed state, bound request cleanup to the evidence key and prepared the exact held-response regression. Independent review of that correction found no remaining source blocker. **Compiled acceptance is still pending** at this note's current revision. No local UI patch or browser run was performed by this lane.
