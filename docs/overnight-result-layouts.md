# Result presentation layouts

Implemented 12 October 2026. This work changes how computed marketing results are arranged; it does not change scoring or outcome selection.

## Creator experience

The Marketing tab now begins with **Choose how the result unfolds**, a simple three-choice control:

- **Stacked**: the existing sequence of introduction, overall score, priorities, reasons, advice, category details, conditional sections and final action.
- **Score overview**: overall score and a compact overview of every category and its answer coverage first, followed by priorities/advice, complete category details and conditional sections. Recommendations without score categories lead with their matching reasons; no scores or categories are fabricated.
- **Action plan**: configured advice, practical priorities and the main action first. The full scoring evidence, every category and conditional sections remain below.

The existing answer-combination simulator renders the selected layout using the real evaluator on the current unsaved draft. It explicitly creates no response or lead and does not claim to validate every possible journey.

## Data integrity and compatibility

- `marketing.presentation.layout` is optional, with `stacked` as the default. Supported values are `stacked`, `score_overview` and `action_plan`.
- Evaluation copies an explicit presentation object into `MarketingResult`. Result rendering depends on that saved object, never on a later draft. Older results without the field use the original stacked order.
- The scoring implementation is unchanged: numeric values, equal category weighting, eligibility, exclusions, ties, mapped zeros, missing-answer treatment, category minimums, selected outcome, denominators and priorities are identical across layouts.
- No layout hides a low or insufficient category. Overview summaries include all categories, and all layouts retain their full details and scored/applicable question counts. Missing coverage remains “Not enough information”; an unavailable overall score receives no invented advice or band CTA.
- Existing result-section conditions are evaluated on the server and copied into the saved result as before. Layouts display that already selected content without reevaluating conditions from a current draft.
- Main and section CTA links retain the same `onOfferClick` callback and existing per-attempt tracking deduplication.
- No database migration, QuizPlayer change or schema-file change was required for this interface.

## Files

- `lib/marketing.ts`: optional presentation schema/type and computed-result snapshot.
- `components/MarketingResultCard.tsx`: three arrangements built from shared score, coverage, priority, evidence and section renderers.
- `components/ResultLayoutEditor.tsx`: reusable three-choice presentation editor.
- `components/MarketingStudio.tsx`: layout control and explicitly labelled calculated-result preview.
- `tests/fixtures/result-layouts.cjs`: synthetic scorecard fixture.
- `tests/result-layouts.cjs`: evaluator/snapshot regressions.
- `tests/browser-result-layouts.cjs`: local-only Playwright regression suite and screenshots.

## Validation

- Unit suite passes complete, all-zero, mixed and insufficient answer combinations across all three layouts; it checks exact numerical/result invariance, category denominators, conditional content, in-memory snapshot isolation, JSON persistence, legacy default and recommendation-quiz invariance.
- Existing `tests/result-sections.cjs` and `tests/journey-testing.cjs` pass.
- Local Playwright passes creator selection/autosave/reload, actual player submissions, stored layout snapshots, conditional sections, 0% category visibility, insufficient-score simulation, 390px mobile overflow, primary and section CTA callbacks, tracking deduplication, older results after later publications, and persisted legacy-result fallback.
- TypeScript check passes. Scoped ESLint reports 0 errors and 2 existing warnings (result-section image element and the ignored condition field).
- Desktop and mobile screenshots are saved under `../pippi-overnight-2026-10-12/result-layouts/`.

## Boundaries

This is structured presentation, not an unrestricted drag-and-drop results-page builder. No new advice is generated by choosing a layout. Conditional section order and content remain creator-controlled in the existing editor. Layout selection currently lives in the full editor's Marketing tab; the component can also be placed in guided Results without changing the evaluator. Tests use isolated local synthetic quizzes; no production records, real emails, external AI or deployments were used. The parent task owns the shared production build and result-link/print integration.
