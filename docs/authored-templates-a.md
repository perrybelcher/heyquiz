# Personality and knowledge collection: editorial specification

Six templates, 92 substantive questions. Authored 29 October 2026. No contact or display fields count toward the total. All questions are required single choices with an explicit neutral answer; no branching shortens the path. The themes appear as existing question descriptions, without additional navigation. Design uses the existing editable form theme.

## Outcome blueprints and limits

Personality asks about preferences, not competence, morality or clinical traits. Each question gives exactly one equally weighted opportunity for each of three profiles. The answer order rotates, while stable IDs keep references intact. Two matching answers are the minimum evidence to select a profile; all neutral or a single positive answer returns the fallback. This is an illustrative minimum, not statistical confidence. The largest count wins; equal counts use displayed profile order (planner, explorer, connector), not a claim that the first is a better fit. No percentages or grades are presented. Descriptions say “your selected situations lean toward” rather than claiming every characteristic applies. The reasons quote only answers actually selected. CTA labels are editable and URLs empty; creators must configure any destinations they intend to use.

| Template | Three outcomes | Distinguishing evidence |
|---|---|---|
| Discover your working style (30) | Structured planner; Practical explorer; Collaborative connector | Explicit structure/criteria; trials/alternative approaches; people/shared understanding |
| What kind of traveller are you? (8) | Considered planner; Curious explorer; Local-life connector | Planned experiences; discovery/detours; local participation |
| Discover your home style (8) | Calm and considered; Expressive and collected; Warm and welcoming | Simplicity/function; character/contrast; comfort/hosting |

Each result gives one practical activity and a balancing consideration, without products, fabricated offers or scientific claims. “Not sure / it depends” adds no evidence. All three styles have a feasible answer in every situation, so a participant can reach any result on a complete path.

Knowledge answers one point per correct answer; wrong and unsure answers earn zero. Three illustrative feedback bands cover 0–49, 50–79 and 80–100 inclusive. The app's editable passing threshold is 70%; the feedback bands are learning summaries, not certification. Explanations remain available after completion. Correct choices rotate position. Factual questions are distinct from scenario-based applications; source guidance supports the principles, while the specific fictional situations are original examples.

## Knowledge source verification

Sources below were opened or read in search results on 29 October 2026. They support general principles, not guarantees. No medical caffeine limits or jurisdiction-specific consumer-rights answers are included. Security examples defer real incidents to the organization's process; no quizzes ask participants to open actual suspicious links. The `.example` domains are reserved illustrative text, not clickable destinations. Wording is original, concise paraphrase and application; no source passages are reproduced.

### Suspicious messages: six themes of five

Source keys:

- S1: [FBI, Spoofing and Phishing](https://www.fbi.gov/how-we-can-help-you/common-frauds-and-scams/spoofing-and-phishing) — sender impersonation and independent checks.
- S2: [FTC, Recognize and Avoid Phishing](https://consumer.ftc.gov/articles/how-recognize-avoid-phishing-scams) — unexpected requests, trusted contact routes and MFA.
- S3: [FTC, QR-code scams](https://consumer.ftc.gov/consumer-alerts/2023/12/scammers-hide-harmful-links-qr-codes-steal-your-information) — QR destinations and independent verification.
- S4: [CISA/NSA/FBI/MS-ISAC phishing guidance](https://media.defense.gov/2023/Oct/18/2003322402/-1/-1/1/CSI-PHISHING-GUIDANCE.PDF) — malware attachments and chat-based phishing.
- S5: [CISA Counter-Phishing Recommendations](https://www.cisa.gov/sites/default/files/publications/Capacity_Enhancement_Guide-Counter-Phishing_Recommendations_for_Federal_Agencies_1_0.pdf) — macros, misleading extensions and encrypted archives.
- S6: [FTC verification-code guidance](https://www.militaryconsumer.gov/comment/203860) — never supply a bank verification code to an unexpected caller.
- S7: [FTC, What to Do if You Were Scammed](https://consumer.ftc.gov/articles/what-do-if-you-were-scammed) — compromised credentials and recovery.
- S8: [FTC, Recover a Hacked Account](https://consumer.ftc.gov/articles/how-recover-your-hacked-email-or-social-media-account) — compromised legitimate accounts, provider recovery and forwarding settings.
- S9: [FBI, Business Email Compromise](https://www.fbi.gov/how-we-can-help-you/common-frauds-and-scams/business-email-compromise?source=govdelivery) — verifying payment changes and urgency.
- S10: [FBI IC3, Business Email Compromise](https://www.ic3.gov/CrimeInfo/BEC) — secondary-channel checks and incident response.
- S11: [CISA, Phishing postcard](https://www.cisa.gov/sites/default/files/2024-02/Update%20to%20Phishing%20General%20Security%20Postcard_01.01.2024.pdf) — notifying IT and following reporting protocols.

| Theme | Question → tested principle → source |
|---|---|
| Sender identity | display-name → display label is not proof → S1; lookalike → changed domain → S1; familiar-account → compromised real accounts → S8; personal-details → targeted impersonation → S9; mobile-sender → inspect full address → S10 |
| Links | link-label → destination differs from text → S11; qr → independent delivery check → S3; short-link → hidden route warrants verification, not automatic guilt → S2; account-alert → check independently → S2; chat-link → phishing beyond email → S4 |
| Attachments | invoice-file → unrequested files → S2; macros → active content → S5; forwarded-file → forwarding does not certify safety → S1; double-extension → disguised executable → S5; zip-password → encryption is not safety → S5 |
| Credential requests | password-request → do not disclose passwords → S1; verification-code → code privacy → S6; mfa → extra protection, not immunity → S2; shared-password → reused credential exposure → S7; account-recovery → provider's recovery route → S8 |
| Payment requests | bank-change → verify changed details → S9; secret-payment → controls despite urgency → S9; callback → independently known number → S9; thread → account compromise in conversations → S10; transfer-sent → prompt bank contact → S10 |
| Verification/reporting | report-channel → approved incident channel → S11; clicked → report actual interaction accurately → S11; unsure → known independent contact → S2; recovery-check → forwarding/recovery settings → S8; help-colleague → enable prompt reporting → S11 |

The reporting scenarios apply the reporting principle rather than prescribe technical remediation. The “clicked” question's exact information checklist is an editorial operational example; organizations should adapt it to their own procedure.
